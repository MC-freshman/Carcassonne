# 卡卡颂 · 桌游模拟器（Windows 桌面端）

基础版卡卡颂完整规则实现：72 张地牌、本地热座 2–6 人、三档 AI、局域网联机。
规则依据 CAR v7.4（Complete Annotated Rules；官方 PDF 因版权不入库，本地开发可放在 `docs/S-CAR_v7.4.pdf`）。
当前版本 **v0.15.1**（M1–M21 全部完成：基础版 + 大扩展「客栈与大教堂 / 商人与建造者 / 公主与龙 / 修道院与市长 / 国王与强盗男爵 / 河流 II / 教堂与异端 / 卡卡颂伯爵 / 桥城堡集市 / 塔 / 山丘与羊 / 命运之轮」+ 迷你扩展八件套「围攻 / 节日 / 金矿 / 法师与女巫 / 强盗 / 麦田怪圈 / 隧道 / 幽灵」共 20 个扩展开关；联机增强 + 前瞻 AI + 一键发布管线。排期见 `docs/里程碑方案.md`，发布记录见 `docs/发布记录.md`）。

## 快速开始

```bash
# 已打包用户：从 GitHub Releases 下载便携 zip，解压后双击 卡卡颂.exe（无需 Python）

# 源码运行（需 Python 3.9+，第三方依赖仅 Pillow）
git clone https://github.com/MC-freshman/Carcassonne.git
cd Carcassonne
pip install -r requirements.txt
python game/main.py            # 启动：选择 单机 / 建房 / 加入
python game/main.py --quick    # 调试：玩家 vs AI 快速开局
python game/main.py --demo     # 演示：纯 AI 自动对局

# 重新打包
python build_release.py        # 一键发布：验证门禁 → EXE + 便携 zip + SHA256 清单 + 自动发布记录

# 全部验证（约 2 分钟）
python -m pytest game/tests -q && python verify_v1.py 20 \
  && python verify_v1.py 8 --inns --traders --king --river --shrine --count --bcb --mini --tower --hs --wheel \
  && python verify_ai.py && python verify_ui.py && python verify_interact.py \
  && python verify_network.py && python verify_netui.py
```

## 扩展开关

20 个扩展（9 个大扩展 + 迷你八件套 + 塔 / 山丘与羊 / 命运之轮）在单机「开局设置」
与「建立联机房间」里以**可折叠面板**呈现：

- 默认折叠，只占一行「▸ 扩展（已选 0 / 20）」——小屏也不会顶出屏幕
- 点标题展开：列表限高滚动（滚轮可用），右侧「全选 / 清空」一键切换
- 展开后窗口底边超出屏幕时自动上移，底部按钮始终可见
- 联机建房时扩展需全员统一，创建房间后不可更改

## 联机

- **建房**：选「建立联机房间」→ 总人数 / AI 数 / 房主名 → 创建后窗口显示本机 IP 与端口（默认 37241，被占时自动换）
- **加入**：同一局域网内输入主机 IP + 端口 + 名字加入
- 房主人齐后点「开始对局」；AI 座位与断线玩家由主机代打；断线后同名可重连
- 架构：**主机权威**——服务器持有唯一规则引擎，客户端只发操作（放置/部署/跳过/弃牌），主机校验后广播完整状态快照（单快照约 3KB）

## 操作

| 阶段 | 操作 |
|---|---|
| 放置地牌 | 黄色高亮格 = 当前朝向的合法位置；点击放置；悬停显示预览 |
| 旋转 | 右侧「↻ 旋转」按钮或按 `R` 键（提示栏会显示哪些朝向可行） |
| 无处可放 | 「弃牌重抽」按钮自动变为可用（需确认全员同意的规则场景） |
| 部署随从 | 放牌后点击牌上黄色圆钮（骑士/强盗/僧侣/农夫），或点面板按钮 / 「跳过部署」 |
| 终局 | 牌堆摸空自动终局结算（未完成特征 + 农场），弹出结算窗 |

## 架构与数据流

```
┌─────────────┐   ┌──────────────────────────────────────────┐
│  UI (ui.py) │──▶│  引擎 CarcassonneEngine (engine.py)      │
│  输入/渲染   │   │  ├─ tile_data: 72 张牌定义（唯一数据源）  │
│             │◀──│  ├─ board: 并查集特征连通（完成/多数数据） │
│  AI (bot_ai)│──▶│  └─ 计分集中（pts_map/_final_award/农场） │
└─────────────┘   └──────────────────────────────────────────┘
        ▲ 联机：主机权威
        └─ server(权威引擎) ──快照──▶ client ──▶ 本地显示副本(from_dict)
```

- **规则只存在于引擎**：UI/AI/联机全部通过引擎公开接口操作；客户端联机时仅持有
  `from_dict` 重建的显示副本做交互预判，权威结算永远在主机。
- **计分集中**：游戏内计分（`pts_map`）、终局（`_final_award`）、农场块三处；
  扩展倍率（客栈/大教堂）只改这三处 + 特征旗标。
- **牌面数据独立**：换官方贴图只需 `assets/tiles` 同名替换；
  加扩展牌只需在 `tile_data.py` 追加并同步校验表。

| 文件 | 核心内容 | 扩展点 |

## 开发约定

1. **规则改动只进引擎**：UI/AI/联机不得实现规则逻辑；计分集中在 engine 三处。
2. **牌面数据必配校验**：改 `tile_data.py` 后跑 `validate()`（总量/拓扑分布/段-边一致）。
3. **扩展开关隔离**：新规则默认关闭（`expansions` 参数），基础版行为不变。
4. **每改动跑全量回归**：见上表 7 套（含联机），新增用例随功能补进 `game/tests/`。
5. **UI 坐标统一画布坐标系**：鼠标事件先 `canvasx/canvasy` 再算网格；
   网格原点用 `GRID_ORIGIN` 常量，禁止用视图相关量做原点。
6. **素材可再生成**：`python -m game.art` 强制重建全部贴图（含 4 旋转）。
7. **测试环境禁定时器**：`verify_*` 中对 `App.after` 打桩（lambda 丢弃），
   避免 AI 定时回调造成幽灵推进；交互一律手动驱动。

## 规则实现口径（对照 CAR v7.4）

- **城市计分**：2 分/牌 + 2 分/旗帜（同牌双段同城只计 1 张）；小城市规则已按现行版废除
- **道路**：交叉口/丁字路口终止一切道路，每条支路为独立道路段（CAR 脚注 15/358）
- **修道院**：自身 + 周围 8 格齐即完成得 9 分；邻格落牌时自动检测触发
- **多数判定**：最多者得分；平局均得全额；同色多米宝不翻倍（脚注 21）
- **终局**：未完成道路 1/牌、城市 1/(牌+旗帜)、修道院 1/格；农夫不归还
- **农场（第三版口径，脚注 32/33）**：每个农场多数农夫者得 3 分 × 毗邻完成城市数；一个完成城市可被多个农场分别计分
- **无法放置的牌**：经「弃牌重抽」处理（模拟全员同意）

## 扩展（M16：修道院与市长）

单机设置或建房时勾选「修道院与市长」（12 张，可与其他扩展叠加）：

## 扩展（M9：商人与建造者）

单机设置或建房时勾选「商人与建造者」（可与客栈/大教堂叠加，牌堆至多 113 张）：
