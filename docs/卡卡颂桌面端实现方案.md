# 卡卡颂桌面端实现方案

> 📌 方案定位：基于 docs/S-CAR_v7.4.pdf（卡卡颂完整规则参考 CAR v7.4，339 页）与同目录既有「山中小屋」桌面端工程模式，给出卡卡颂 Windows 桌面端的可执行实现方案。本方案回答三件事：做什么范围、怎么把规则数字化、用什么技术栈和节奏落地。

## 设计首页

### 产品定位与背景

一款 Windows 桌面端卡卡颂桌游数字化应用，个人开发、非商业。整体沿用「山中小屋」已验证的工程管线：**Python + Tkinter 桌面端 → PyInstaller 打包 EXE → socket 局域网联机 → 内置 AI**，规则引擎与 UI 解耦，供单机、AI、联机三端共用。

### 目标玩家与游戏模式

| 维度 | 设定 |
|---|---|
| 玩家 | 自己与朋友，2–6 人 |
| 本地热座 | 同一台电脑轮流操作，2–6 人 |
| 单人 vs AI | 1 名人类 + 1–4 名 AI，三档难度 |
| 局域网联机 | 同一局域网内 2–6 人，主机权威同步 |
| 单局时长 | 约 30–45 分钟 |

### 核心幻想与设计支柱

核心幻想：扮演中世纪领主，通过放置地块扩展疆土，部署米宝（骑士、强盗、僧侣、农夫）争夺道路、城市、修道院与农场的控制权，最终以分数决出领主。

| 设计支柱 | 含义 |
|---|---|
| 规则忠实 | 基础版 72 张牌完整规则忠实实现；争议规则以 S-CAR 注解为准，不擅自简化农场、多数判定等关键规则 |
| 操作直观 | 抽牌即见、拖放地块、点击部署米宝；合法放置位置实时高亮，旋转一键完成 |
| 反馈清晰 | 计分即时滚动、特征完成弹出提示、多数判定透明化（展示各色米宝数量） |

### 核心回合循环

每位玩家按顺时针依次执行一个回合，回合固定三步：**抽牌 → 放置地块 → 部署米宝（可选）**，随后立即结算本次放置所完成的道路、城市或修道院。最后一轮将 72 张牌全部放置完毕后进入终局计分。

> 📊 核心回合循环图示见 docs/gameflow.svg（飞书文档内为可编辑画板）

### 范围与非目标

| 范围 | 内容 |
|---|---|
| P0（首版） | 基础游戏：72 张地牌（含起始牌），2–6 人，完整回合流程、计分、终局与农场计分 |
| P1（后续里程碑） | 大扩展逐步接入：客栈与大教堂、商人与建造者、公主与龙、修道院与市长等，每接入一个按同一规则引擎扩展 |
| 非目标 | 商业发布；跨平台（首版仅 Windows）；公网在线匹配；首版一次性支持全部扩展 |

## 基础规则数字化设计

卡卡颂的数字化本质是「**牌面拓扑 + 特征连通图 + 计分事件**」三件事。下面按数据建模顺序给出规则拆解，所有边界均以 S-CAR v7.4 为准。

### 地块拓扑模型

每张地牌需建模五个要素，其中「段连接」是建模的关键——决定哪些边或中心属于同一个可放置米宝的特征段：

| 要素 | 数据表示 | 说明 |
|---|---|---|
| 四边地形 | edges: [上,右,下,左]，每边 ∈ 城市(c)/道路(r)/田野(f) | 放置匹配的唯一依据；角对角不算连接 |
| 段连接 | 每张牌内部定义：哪些边/中心属于同一特征段（段编号） | 同一牌上两段城市若同属一城则只计 1 段 |
| 中心特征 | 修道院 / 交叉口 / 无 | 修道院独立成段；交叉口是道路终点 |
| 旗帜 | 城市段是否含盾徽（布尔） | 仅影响所在城市段计分，不影响整牌 |
| 旋转 | 0°/90°/180°/270° 四态 | 旋转改变边序但不改变段内拓扑 |

### 基础版牌面构成

基础版共 72 张地牌（含 1 张深色反面的起始牌），按四边拓扑（上右下左，c=城/f=田/r=路）分类如下。数据取自 S-CAR《Consolidated Tile Reference》，实现时逐张核对牌面图形：

| 拓扑类型（上右下左） | 数量 |
|---|---|
| cccc（全城） | 1 |
| cccf | 4 |
| cccr | 3 |
| ccff | 7 |
| ccrr | 5 |
| cfcf | 6 |
| cfff | 5 |
| cfrr | 3 |
| crfr | 4 |
| crrf | 3 |
| crrr | 3 |
| ffff（全田） | 4 |
| fffr | 2 |
| ffrr | 9 |
| frfr | 8 |
| frrr | 4 |
| rrrr（全路） | 1 |

合计 **72** 张。其中同拓扑的牌还需区分内部段结构与旗帜位置（如 7 张 ccff 里有 3 种不同画法），牌面 ID 需唯一编号，作为素材与数据的关联键。

### 放置合法性

- 新牌至少一边与已有地块边相邻；**角对角接触不合法**。
- 所有相邻边的地形必须同类匹配（城对城、路对路、田对田）；不能只检查单边。
- 目标格必须为空；棋盘采用稀疏字典（坐标 → 地块），无固定尺寸。
- 无法合法放置时（全员同意），该牌移出本局，玩家重抽一张。

### 特征连通与并查集

城市、道路、田野分别维护一套**并查集（Union-Find）**。放置地块时，把新牌的段与相邻同类型段合并。每个连通分量（特征段）维护：段内牌数、旗帜数、米宝列表（颜色→数量）、是否完成。这是完成检测、多数判定与计分的统一数据源。

> ⚠️ 田野（农场）与道路、城市共用同一并查集思路，但没有「完成」概念，只用于终局统计「每个完成城市相邻哪些农场」。农场被道路、城市和棋盘边缘分隔，实现时以「边是否被非田野阻挡」判断连通。

### 完成检测

| 特征 | 完成条件 |
|---|---|
| 道路 | 两端均为终点（交叉口/城市边/修道院），或形成闭环 |
| 城市 | 段被城墙完全围合、内部无缺口 |
| 修道院 | 自身 + 周围 8 格全部被地块占据 |

完成判定在「放置地块后、部署米宝前」完成登记；同回合允许「放置→部署→立即计分→归还」。

### 计分规则

#### 游戏内计分（基础版）

| 特征 | 计分 | 结算后 |
|---|---|---|
| 完成道路 | 1 分/张牌 | 米宝归还 |
| 完成城市 | 2 分/城市段 + 2 分/旗帜 | 米宝归还 |
| 完成修道院 | 9 分（自身 + 周围 8 张） | 米宝归还 |
| 多个米宝同一特征 | 最多者得分；平局均得全额 | 参与米宝全部归还 |

#### 终局计分

| 特征 | 计分 |
|---|---|
| 未完成道路 | 1 分/张牌 |
| 未完成城市 | 1 分/城市段 + 1 分/旗帜 |
| 未完成修道院 | 1 分/张（自身 + 周围） |
| 农场 | 每个毗邻或包含的完成城市 3 分；该农场米宝最多者得分，平局均得 |

农夫整局不归还，终局统一结算。一个城市可被多个农场各计一次 3 分。

### 计分板

计分板为 0–50 循环轨道。数字实现：`score = 圈数 × 50 + 当前格`；过「0」时显示 50/100 分牌提示。UI 可复用 docs 中的计分轨道 JPG 作为贴图，或程序化绘制轨道。

### 多数判定与平局

- 同特征多个米宝：**数量最多者得分**；同色多个米宝不翻倍，仅参与多数比较。
- 平局：所有平局玩家均得全额分数。
- 最终胜负：总分最高者胜；平局按规则书 RGG 口径「共享胜利」处理，UI 上并列显示。

## 技术方案

### 技术栈

| 层次 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.10+ | 与山中小屋一致，复用验证与打包经验 |
| UI | Tkinter（Canvas 绘制棋盘） | 标准库、免依赖；Canvas 足够承载网格地块与拖放 |
| 规则引擎 | 纯 Python，与 UI/AI/联机解耦 | 单机、AI、联机共用同一权威规则 |
| 打包 | PyInstaller → 单 EXE | 沿用山中小屋 release 管线 |
| 联机 | socket（TCP）主机/客户端 | 复用 net/ 目录模式；主机权威同步 |
| 测试 | pytest + verify_*.py | 单元测试 + 自动化对局 + UI 按钮校验 |

### 核心数据模型

**核心数据结构示意**
```python
class Terrain(Enum): CITY, ROAD, FIELD = 1, 2, 3

class Tile:
    tile_id: str            # 唯一牌面 ID（素材关联键）
    edges: list[Terrain]    # [上, 右, 下, 左]
    segment_of_edge: dict   # 边 -> 段编号（段连接关系）
    center: Center | None   # 修道院 / 交叉口
    pennant: bool           # 城市段是否含旗帜

class PlacedTile:
    tile: Tile
    x: int; y: int
    rotation: int           # 0/90/180/270

class Feature:              # 并查集节点（城市/道路/田野各自一套）
    kind: Terrain
    tile_ids: set           # 覆盖的牌
    pennants: int
    meeples: Counter        # 颜色 -> 米宝数
    complete: bool          # 田野恒为 False

class Player:
    color: str
    meeples: list           # 8 个米宝（1 个作计分标记）
    score: int              # 由计分板换算
    lap: int
```

### 规则引擎接口

**引擎对外接口（UI/AI/联机共用）**
```python
class CarcassonneEngine:
    def legal_placements(self, tile) -> list[(x, y, rotation)]
    def place_tile(self, player, x, y, rotation) -> PlacementResult
    def deploy_meeple(self, player, feature_id) -> DeployResult   # 可选跳过
    def completed_features(self) -> list[Feature]                 # 本次放置后
    def score(self, feature) -> int
    def final_scoring(self) -> list[ScoringEvent]                 # 终局
    def state_snapshot(self) -> bytes                             # 联机快照
```

引擎为纯状态对象，AI 可拷贝快照做前瞻，联机主机持有权威引擎、客户端只发操作。

### 界面设计

| 区域 | 内容与交互 |
|---|---|
| 中央棋盘 | Canvas 网格；悬停显示合法位置高亮，点击放置；拖拽或点击旋转 |
| 右侧信息面板 | 当前抽到的牌、可部署角色、玩家列表（颜色/米宝余量/分数）、操作按钮 |
| 底部计分板 | 0–50 循环轨道 + 各色计分标记；过 0 提示 50/100 分 |
| 结算弹层 | 完成特征计分明细（各色米宝数与得分）、多数判定展示 |

### AI 设计

对每张可放置牌枚举全部「位置 × 旋转 × 部署动作」组合，按启发式打分，难度通过分数阈值与随机扰动调节：

| 难度 | 策略 |
|---|---|
| 简单 | 随机合法放置，基本不部署 |
| 普通 | 贪心：优先立即完成特征、优先延伸自己米宝所在特征、避开封死自己米宝 |
| 困难 | 普通策略 + 阻断对手（抢占多数）、评估农场终局价值、前瞻 1 步 |

### 联机架构

复用山中小屋 net/ 模式，采用**主机权威**：服务器运行权威引擎，客户端发送操作指令，服务器校验、结算后广播状态。关键消息：`JOIN / READY / DRAW / PLACE / DEPLOY / SCORE / STATE / TURN_END`。断线重连通过状态快照恢复。

> 💡 首版联机可只做「行动同步 + 快照」，不做逐帧渲染同步——卡卡颂是回合制，主机结算后广播一次状态即可，复杂度远低于实时联机。

### 验证与测试

- **牌面数据校验**：72 张牌总量、拓扑分布与规则书逐项一致。
- **规则引擎单测**：放置合法性、完成检测、计分、终局农场，以 S-CAR 计分示例作 golden 用例。
- **自动化对局**：引擎随机对局跑通全牌，断言牌数耗尽与终局可结算。
- **UI 校验**：verify 脚本检查按钮可点、窗口不同尺寸布局不塌（吸取山中小屋「查看玩家」按钮被压缩的教训）。
- **联机校验**：双客户端模拟完整对局，校验状态一致与断线重连。

## 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 牌面数据录入错误 | 规则失真、放置错判 | 从规则书逐张核对；自动校验总量 72、拓扑分布一致 |
| 农场连通与终局计分复杂 | 实现难、易错 | 并查集 + 终局专用「完成城市→农场」邻接遍历；对照 S-CAR 农场示例用例 |
| 多数判定与平局边界 | 计分错误 | 多数逻辑集中引擎实现；golden 用例覆盖平局、同色多米宝场景 |
| Tkinter 交互表现受限 | 体验打折 | 棋盘用 Canvas 自绘；如遇硬伤可升 PyQt，引擎不动 |
| 联机状态不一致 | 不同步 | 主机权威 + 唯一操作序 + 状态快照回滚 |
| UI 布局在异宽屏塌陷 | 按钮不可点 | grid 布局 + 最小宽度；多分辨率校验脚本 |

## 验收标准

1. 基础版 72 张牌完整录入，规则以 S-CAR v7.4 为准且无擅自简化。
2. 2–6 人本地热座可完整打完一局（含终局农场计分），计分板循环正确。
3. 单人 vs AI 可玩，三档难度出牌合法且不阻塞。
4. 局域网 2–6 人联机可完整对局，断线可恢复。
5. 自动验证脚本（牌面、引擎、UI、联机）全部通过。
6. PyInstaller 打包 EXE 可独立运行，发布包含使用说明与版本说明。
